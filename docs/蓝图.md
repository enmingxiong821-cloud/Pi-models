# pi-model（`pmh`）设计蓝图

> 状态：v0.1 已实现并可用（本机验证通过 + CI 矩阵）。本文档描述"做成什么样、为什么这样做、边界在哪"。
> 最近更新：2026-10-17

---

## 1. 定位与目标

### 1.1 要解决的问题

pi 的上手流程（`/login`）只列内置模型厂商。用户想接第三方中转站（如 Crow5、NewAPI、one-api 自建网关），
会发现"没地方填 URL 和 Key"。实际上 pi **原生支持**任意兼容端点，只是需要手写 `~/.pi/agent/models.json`，
而且要为每个模型补齐上下文窗口、最大输出、推理能力、输入模态、价格等元数据，否则上下文管理和费用显示都不准。

### 1.2 目标

1. **接入**：填 URL + Key 就能用，最好一条命令或一次粘贴完成。
2. **切换**：切换成本接近零 —— pi 内一个快捷键、命令行一个短词。
3. **不搞坏现状**：只写 pi 自己的配置文件，写前备份，密钥不落日志。
4. **零依赖、跨平台**：只用 Node 标准库；Windows / macOS / Linux / WSL / Termux 可用。
5. **可验证**：每个平台分支、每条命令都有可在任意机器上跑的测试。

### 1.3 非目标（刻意不做）

| 不做 | 原因 |
|---|---|
| 不做代理网关 / 转发流量 | 那是 NewAPI、one-api、LiteLLM 的活；本工具只做配置与切换 |
| 不做 GUI / Web 面板 | 已有 [Wing900/Pi-switch](https://github.com/Wing900/Pi-switch)、[Raingor/pi-web-switch](https://github.com/Raingor/pi-web-switch)；本工具走终端优先 |
| 不管理上游计费、不做用量统计 | 数据在中转站侧，本地算不准 |
| 不修改 pi 的任何官方文件 | 只新增/修改 `models.json`、`auth.json`、`settings.json`，并且写前备份 |
| 不内置任何中转站白名单 | 任何 OpenAI / Anthropic / Responses 兼容端点都能接 |

## 2. 用户旅程

### 2.1 首次接入（目标：≤ 30 秒）

```text
路线 A（一键）     pmh quick                      # 地址+Key 已在剪贴板时零输入
路线 B（一键带参） pmh quick https://x.crow5.com sk-xxx
路线 C（向导）     pmh add                        # 逐项问：地址 → 名称 → Key（掩码）→ 预览模型 → 确认
路线 D（老手）     pmh add crow5 --base <url> --key <key> --api-rule "^claude=anthropic-messages"
```

四条路都走同一个内核：`cmdAdd`。完成后都会落到「读模型列表 → 补元数据 → 写配置 → 挑默认模型」。

### 2.2 日常切换（目标：≤ 2 秒）

```text
pi 内部      /switch              选择器（中转站排最前）
             /switch sonnet       关键词直接切
             Ctrl+Shift+M         快捷键
命令行       pmh pick             ↑↓ 选择器
             pmh use sonnet       关键词模糊 → 设为默认
             pmh run sonnet       关键词模糊 → 直接启动 pi
             pi-crow5             （pmh alias 生成的分站快捷命令）
```

### 2.3 维护

```text
pmh sync crow5      上游上新模型后重新拉取（保留你手改过的字段）
pmh test crow5      探 /v1/models + 真发一条最小请求
pmh doctor          环境体检：pi 版本、配置路径、TTY、剪贴板工具、启动器
pmh rm crow5 --purge-key
```

### 3.2 一次"接入"的数据流

```text
用户输入 URL + Key
   │
   ├─ 归一化地址：rootOf() 去掉尾部 / 与 /v1；按 api 类型决定要不要补 /v1
   ├─ 推断 provider 名：suggestName() 从域名取（api.openai.com → openai）
   ├─ 读模型列表：GET {root}/v1/models（OpenAI 用 Bearer，Anthropic 用 x-api-key）
   │
   ├─ 元数据匹配（catalog.mjs）
   │    ① 精确命中 pi 官方目录  → 直接用官方 name/上下文/价格
   │    ② 归一化后命中          → 去 vendor 前缀、去 :free、去日期尾号、点横线互转
   │    ③ 模糊匹配              → token 重叠打分
   │    ④ 启发式兜底            → 按家族给保守值（Claude 200K、GPT-5 400K、Gemini 1M…）
   │
   ├─ 写 models.json（providers.<name> = { baseUrl, api, models: [...] }）
   ├─ 写 auth.json（<name> = { type: "api_key", key }）
   └─ 交互模式下：直接弹出选择器 → 写 settings.json 的默认模型
   │
   ▼
pi 启动/刷新时读这三个文件 → /model 与 /switch 里就能看到
```

### 3.3 为什么要有"第二条通道"

CLI 解决的是**配置与批处理**；但"切换"这个动作发生在 pi 的运行期。如果每次都要退出 pi 去敲命令，
切换成本就不够低。所以扩展直接注册 pi 内的命令与快捷键，用 `pi.setModel()` 切当前会话，
`pmh` CLI 只负责把配置写好、把扩展装进去。两者职责不重叠、也不互相依赖（扩展不调用 CLI）。

## 5. 数据模型

### 5.1 `models.json`（本工具写入的部分）

```jsonc
{
  "providers": {
    "crow5": {
      "name": "crow5",                       // 显示名，默认与 id 相同
      "baseUrl": "https://x.crow5.com/v1",   // openai-* 带 /v1；anthropic-messages 用根地址
      "api": "openai-completions",           // 该 provider 的默认协议
      "models": [
        {
          "id": "claude-sonnet-4-5",         // 必填，传给上游的 model 名
          "name": "Claude Sonnet 4.5",       // pi 里显示的名字
          "reasoning": true,                 // 是否支持思考
          "input": ["text", "image"],        // 输入模态
          "contextWindow": 200000,           // 上下文窗口（影响压缩与进度条）
          "maxTokens": 64000,                // 单次输出上限
          "cost": { "input": 3, "output": 15, "cacheRead": 0.3, "cacheWrite": 3.75 },
          "api": "anthropic-messages",       // 可选：覆盖 provider 级协议
          "baseUrl": "https://x.crow5.com"   // 可选：模型级覆盖（与 api 一起用时需要）
        }
      ]
    }
  }
}
```

规则要点（来自 pi 的 `models.schema.json`）：

- `api` 可选值：`openai-completions`、`openai-responses`、`anthropic-messages`；**模型级优先于 provider 级**。
- `models[]` 里的条目按 `id` 替换同名模型；`modelOverrides{}` 则用于改已有（内置/扩展）模型的元数据而不替换列表。
- 凭据解析顺序：命令行 `--api-key` → `auth.json` → `models.json.apiKey` → 环境变量。
  **解析不到凭据的模型不会出现在 `/model` 里**（最常见的"配了却看不到"原因）。

### 5.2 `auth.json`

```json
{ "crow5": { "type": "api_key", "key": "sk-..." } }
```

写入策略：默认只写这里（与 pi 自身的 `/login` 存储一致）；`--key-in models` 才写进 `models.json`。

### 5.3 `settings.json`（本工具触碰的字段）

| 字段 | 用途 | 由谁写 |
|---|---|---|
| `defaultProvider` / `defaultModel` | 新会话的默认模型 | `pmh use` / `pmh quick` / `/switch-save` |
| `defaultThinkingLevel` | 默认思考级别 | `pmh use --thinking <级别>` |
| `enabledModels` | 限定 `/model` 与 `Ctrl+P` 的候选范围 | `pmh scope` |

### 5.4 内部数据结构

| 结构 | 形状 | 说明 |
|---|---|---|
| catalog index | `Map<modelId, meta>` | 由 `providers/data/*.json` 展平；同 id 时非 openrouter 源优先 |
| catalog entry | `{ id, name, reasoning, input, contextWindow, maxTokens, cost, type, api }` | `type` 由 key 前缀（`chat:`/`image:`/`classifier:`）得出 |
| 模型条目 | `{ entry, match, source }` | `source` ∈ {pi 官方目录, 启发式推断}；`match.method` ∈ {exact, normalized, fuzzy} |
| 解析目标 | `{ provider, model, hits[], query, exact }` | `resolveTarget()` 的返回值，多命中时 `hits` 供提示候选 |

## 6. 匹配与推断算法

### 6.1 模型 id 归一化（顺序尝试）

1. 原样
2. 去掉 `:` 之后的路由后缀（`:free`、`:nitro`）
3. 去掉 vendor 前缀（`anthropic/`、`openai/`、`moonshotai/` … 共 20+ 个）
4. 去掉 `@…` 后缀
5. 去掉结尾的 `latest|preview|beta|exp|thinking`
6. 去掉结尾日期（`-20250929`、`-2025-09-29`）
7. 点/横线互转（`claude-sonnet-4.5` ↔ `claude-sonnet-4-5`）

仍不命中则打分：精确 1000 → 结尾匹配 800 → 包含 600 → `provider/id` 包含 500 → 名字包含 400 →
多关键词全覆盖 200+；低于阈值视为未命中。

### 6.2 启发式兜底（官方目录里没有的模型）

| 关键词 | 上下文 | 输出上限 | 输入 |
|---|---|---|---|
| claude / opus / sonnet / haiku | 200K | 64K | text, image |
| gpt-5 / o3 / o4 / codex | 400K | 128K | text, image |
| gemini | 1M | 65K | text, image |
| deepseek | 128K | 64K | text |
| qwen / qwq | 128K | 32K | text |
| kimi / moonshot | 256K | 32K | text |
| glm / zhipu | 200K | 32K | text |
| grok | 256K | 32K | text, image |
| 其他 | 128K | 32K | text |

补充规则：名字含 `-mini|flash|haiku|small|lite|nano` 时输出上限压到 32K；含 `vl|vision|omni` 时加 image；
含 `coder|code` 时只留 text。**价格不猜** —— 官方目录里没有就留空，避免把估算当真。

### 6.3 切换时的排序（pi 内扩展）

```
第 0 组：models.json 里的中转站（按 provider 名、再按模型 id）
第 1 组：当前正在用的 provider
第 2 组：其余（内置厂商）
```

每行显示：`[● 当前] provider/id  · <上下文>/思考/图片/中转`。

### 6.4 provider 名推断

```
tbyunyi-router.crow5.com → crow5        api.openai.com → openai
gw.example.invalid       → example     localhost:11434 → localhost
192.168.1.10:8080        → 192-168-1-10
中文域名（punycode xn--）→ relay（不生成难看的名字）
```

规则：去尾部 TLD（约 20 个常见后缀）→ 去开头的 `www/api/gateway/gw` 等 → 取最后一个标签。

## 7. 命令面

| 命令 | 参数要点 | 副作用 | 退出码 |
|---|---|---|---|
| `add [名称]` | `--base` `--key` `--key-env` `--api` `--api-rule` `--model` `--models-file` `--cost-multiplier` `--no-cost` `--key-in` `--name` `--no-key` `--yes` `--force` `--no-sync` `--dry-run` `--verbose` | 写 models.json / auth.json；交互模式下还写 settings.json | 0 / 1 |
| `quick [地址] [key]` | `--as 名称` | 同 add（等价 `--yes --force`） | 0 / 1 |
| `sync <名称>` | `--keep-missing` `--api-rule` `--cost-multiplier` `--dry-run` | 重写该 provider 的 `models[]`，保留手工字段 | 0 / 1 |
| `key <名称> <key>` | — | 写 auth.json | 0 / 1 |
| `ls` / `models` | `--models` | 只读 | 0 / 1 |
| `use` / `switch` | `[名称[#模型] \| 关键词]` `--thinking` `--allow-builtin` | 写 settings.json | 0 / 1 |
| `scope` | `pattern...` `--clear` | 写 `enabledModels` | 0 / 1 |
| `test <名称>` | `--model` `--no-chat` `--verbose` | 只读（会发一次最小请求） | 0 / 1 |
| `run` | `[目标] [-- <pi 参数>]` | 启动 pi，退出码透传 pi 的 | pi 的退出码 |
| `pick` | `--run` | 写 settings.json（`--run` 时还启动 pi） | 0 / 1 |
| `install-extension` | — | 复制扩展进 `~/.pi/agent/extensions/` | 0 / 1 |
| `alias` | `--shell powershell\|bash` | 只打印，不写文件 | 0 / 1 |
| `rm <名称>` | `--purge-key` | 改 models.json（可选 auth.json） | 0 / 1 |
| `doctor` | — | 只读 | 0 / 1 |

错误语义：任何异常由入口统一捕获 → 打一行 `✖ 原因` → `exitCode = 1`。所有写入都是"临时文件 + rename"的原子替换，
且覆盖前把旧文件复制成 `<文件>.bak-<YYYYMMDD-HHmmss>`。

### 环境变量

| 变量 | 作用 |
|---|---|
| `PMH_AGENT_DIR` | 覆盖 pi 配置目录（等价 `--agent-dir`） |
| `PI_CODING_AGENT_DIR` | pi 官方的配置目录变量，本工具也认 |
| `PMH_PI_BIN` | 指定 pi 启动器路径 |
| `PMH_NO_PROXY` | 不做代理自重启，直连 |
| `PMH_NONINTERACTIVE` | 强制关闭一切提问（脚本/CI/自测） |
| `PMH_REEXEC` | 内部标记，防止代理自重启无限递归 |

## 8. pi 内扩展设计

| 能力 | 实现 |
|---|---|
| `/switch [关键词]` | 无参 → 选择器；有参 → 过滤后唯一命中就直接切，多命中给选择器 |
| `/switch-save` | 同上，并把结果写进 `settings.json` 的默认模型（写前备份） |
| `Ctrl+Shift+M` | 等同 `/switch`（已确认与 pi 默认键位无冲突） |
| 参数补全 | `getArgumentCompletions` 提示所有中转站名 |
| 数据来源 | `ctx.modelRegistry.getAvailable()`（已按凭据过滤）+ 读 `models.json` 判断"谁是中转站" |
| 失败处理 | `setModel` 返回 false → 明确提示"该 provider 没有可用凭据"，不假装成功 |
| 可测试性 | 纯函数（`labelOf/rankModels/filterModels/persistDefault`）导出，另有假 API 测试 |

## 9. 跨平台设计

| 关注点 | Windows | macOS | Linux | WSL | Termux |
|---|---|---|---|---|---|
| 入口 | `pmh.cmd` | `bin/pmh`(sh) | `bin/pmh`(sh) | 同 Linux | 同 Linux |
| 配置目录 | `%USERPROFILE%\.pi\agent` | `~/.pi/agent` | 同左 | 同左；可 `--agent-dir /mnt/c/Users/<你>/.pi/agent` 指到 Windows 侧 | `~/.pi/agent` |
| pi 启动器 | `pi.cmd`（必须走 shell）；路径含空格要加引号 | `~/.pi/agent/bin/pi`、`/opt/homebrew/bin/pi` | `~/.pi/agent/bin/pi`、`/usr/local/bin/pi`、`~/.local/bin/pi` | 同 Linux | 同 Linux |
| 剪贴板 | `pwsh` → `powershell` 的 `Get-Clipboard -Raw` | `pbpaste` | `wl-paste` → `xclip` → `xsel` | 同 Linux | `termux-clipboard-get`（需 termux-api） |
| 换行 | `.cmd/.ps1` = CRLF；`.sh/*.mjs` = LF（`.gitattributes` 强约束） | LF | LF | LF | LF |
| 终端能力 | 现代终端支持 ANSI/raw mode；老控制台自动退化为输序号 | 支持 | 支持 | 支持 | 支持 |

设计原则：**平台差异只允许出现在 `paths.mjs` 与 `clipboard.mjs` 两个文件里**，其余代码只依赖这两个模块提供的抽象；
每个抽象都接受注入参数（`platform` / `exists` / `run`），因此可以在任意系统上单测所有平台分支。

| `tools/smoke-test.mjs` | 15 步 | 接入→元数据→密钥→切换→同步→错误处理→备份→删除→装扩展→名称推断→剪贴板解析→quick 全流程→非交互报错 | 否（fetch 打桩，目录用 `tools/fixtures/catalog`） |
| `tools/extension-test.mjs` | 12 项 | 扩展纯函数 + 命令处理（含选择器、无匹配、凭据缺失分支） | 否 |
| `tools/platform-test.mjs` | 13 项 | 三平台分支：剪贴板候选与回退、启动器查找、引号、名称推断、文本解析 | 否 |
| `tools/rpc-test.mjs` | 3 项 | 真实 pi 以 RPC 模式加载扩展，`/switch gemini` 是否真的改变了会话模型 | 需要本机 pi |

再加 `--real` 变体（真实 HTTP + spawn CLI）供人工在真机跑。
CI：ubuntu / windows / macOS × Node 20 / 22 / 24 共 9 组，跑前四套（没装 pi 的机器上 RPC 套件自动跳过）。

**为什么这样分层**：核心价值是"配置写对了 + 切换真的生效"，所以 ① 用打桩把配置写入逻辑锁死；
② 用假 API 把扩展逻辑锁死；③ 用真 pi 的 RPC 模式验证"扩展被加载且真的切了模型"；
④ 平台分支用注入参数在单机上验证。这样在没有 pi、没有网络、非对应平台的机器上也能给出可信结论。

## 11. 安全与隐私

- **密钥流向**：只写进 pi 的 `auth.json`（或用户显式指定的 `models.json`）；终端输入用掩码（只回显 `*`）；
  输出时一律 `maskKey()` 打码（`sk-12…cdef`）；仓库 `.gitignore` 挡掉 `*.bak-*`、`.tmp-*`。
- **网络出口**：只有两处 —— 拉取用户填写的中转站 `/v1/models`、`pmh test` 的一条最小请求。没有遥测。
- **写入面**：只有 pi 配置目录下的三个 JSON 文件 + `extensions/` 目录；每次覆盖前备份；原子替换避免半截文件。
- **共用机器**：`pmh rm <名称> --purge-key` 可同时清掉凭据。
- **扩展是可信代码**：pi 的扩展在你的进程内运行，所以本扩展不发起任何自己的网络请求，只读配置与调用 pi API。

## 12. 已知限制与风险

| 风险 | 影响 | 现状与对策 |
|---|---|---|
| 中转站价格与官方不同 | 费用显示偏差 | 默认用官方目录价并明确告知；提供 `--cost-multiplier` 与 `--no-cost` |
| pi 版本升级可能改动 models.json schema | 配置可能失效 | 元数据来源与 schema 都读自本机安装目录；`pmh doctor` 会报 JSON 损坏；schema 有 `$schema` 字段可对照 |
| `/login` 与手写 provider 的凭据解析顺序变化 | 模型可能"隐身" | `pmh ls` 明确显示凭据来源（auth.json / env / models.json 明文） |
| 海外端点在国内网络不稳 | 读不到模型列表 | 报错会带上当前代理信息，可 `--proxy` 或 `PMH_NO_PROXY=1`；向导会给一次重试机会 |
| 老式 Windows 控制台不支持 raw mode / ANSI | 向导与选择器体验下降 | 自动退化为明文输入 + 输序号；`PMH_NONINTERACTIVE=1` 可强制 |
| 官方目录里没有的新模型 | 元数据只能估算 | 标注为"启发式推断"，并可用 `pmh sync` 后再手工微调 |
| 私有仓库看不到 CI 结果 | 真机跨平台验证闭环不全 | `gh auth login` 后可读运行日志；或把仓库设为 Public |
| 本机沙箱限制（Docker/WSL 不可用） | 无法在本机跑真 Linux | 用可注入的平台单测 + CI 矩阵替代 |

## 13. 路线图与扩展点

### 13.1 近期（低成本、收益明确）

1. `pmh add` 读 NewAPI 的 `/api/ratio_config` 自动折算真实倍率（`fetchRatioConfig()` 已就位）。
2. `/switch` 支持能力过滤，如 `/switch image claude`、`/switch cheap`。
3. `pmh doctor --fix`：自动修复常见问题（缺 extension、PATH 未生效、JSON 损坏备份回滚）。
4. 发布到 npm（`pmh install-shims` 或 `npm i -g`）—— 注意 npm 上 `pi-model`/`pi-model-hub` 已被占用，需要换名。

### 13.2 中期

5. 虚拟模型：用 pi 的 `registerVirtualModel` 做一个"同站降级/升级"路由（例如主模型 429 时自动切备用站）。
6. 配置分组：把中转站按用途分组（写代码 / 便宜 / 长上下文），`pmh pick --group code`。
7. 一把梭的连通性面板：并发探测所有 provider 的 `/v1/models` 与延迟，输出排序建议。

### 13.3 扩展点（怎么加东西）

| 想加什么 | 改哪里 |
|---|---|
| 新命令 | `src/commands.mjs` 加 `cmdXxx`，`bin/pmh.mjs` 的 switch 里挂上，`printHelp()` 补一行 |
| 新平台 | `src/paths.mjs` / `src/clipboard.mjs` 加候选，`tools/platform-test.mjs` 加分支断言 |
| 新 API 协议 | `src/relay.mjs` 的 `API_KINDS` 与 `probeChat`；`src/commands.mjs` 的 `--api` 校验 |
| 新元数据来源 | `src/catalog.mjs` 的 `loadCatalog()` 与 `matchModel()` |
| 新的分发方式 | 仓库根目录已是标准 pi 包布局（`extensions/`），也可 `npm i -g`（`package.json` 的 `bin`） |

## 14. 关键决策记录（ADR）

| # | 决策 | 理由 | 代价 |
|---|---|---|---|
| 1 | 走 pi 原生 `models.json`，而不是写一个 provider 扩展 | 不挑网关（OpenAI/Anthropic 兼容即可）；升级 pi 时更稳；用户可读可改 | 需要自己实现模型发现与元数据补齐 |
| 2 | 密钥默认写 `auth.json` | 与 pi 自身凭据存储一致；`pmh ls` 能显示来源 | 明文落盘（与 pi 现状一致），需靠文件权限保护 |
| 3 | 元数据优先复用 pi 官方目录 | 与 pi 内部一致，上下文/价格可信；离线可用 | 依赖 pi 安装目录结构，因此加了启发式兜底 |
| 4 | 同时做 CLI 与 pi 内扩展 | 接入是"配置期"动作，切换是"运行期"动作，形态不同 | 两份实现要各自测试（已分成两套测试） |
| 5 | 所有写入先备份 + 原子替换 | 用户配置无价，出错要能回滚 | 目录里会多出 `*.bak-*` 文件（已 gitignore） |
| 6 | 零依赖、只用 Node 标准库 | 中转站用户常在受限环境；避免供应链风险 | 没有现成的 TUI/CLI 框架，选择器要手写 |
| 7 | 平台差异集中在两个模块 + 可注入 | 沙箱/CI 里无法跑所有平台，但要能验证所有分支 | 需要多写一层抽象 |
| 8 | 非 TTY 一律退化而不是报错 | 便于脚本、CI、远程会话使用 | 需要维护两套交互路径 |
| 9 | 价格用 `cost-multiplier` 表达，不猜 | 中转站计价规则各异，猜不如让用户表达 | 用户要多懂一个参数 |
| 10 | 扩展单文件、无外部依赖 | 用户可以单独拷走 / 直接 `pi --extension` 试用 | 与 CLI 的匹配算法有一份重复实现（注释里已标注同步点） |

## 15. 术语表

| 术语 | 含义 |
|---|---|
| 中转站 | 第三方 API 分发服务，通常 OpenAI 兼容，如 NewAPI / one-api 部署 |
| provider | pi 里的模型提供方标识；本工具为每个中转站登记一个 provider |
| 官方目录 | pi 自带的模型元数据（`@earendil-works/pi-ai/dist/providers/data/*.json`） |
| 元数据补全 | 把中转站返回的 model id 映射到官方元数据或启发式默认值 |
| 切换 | 改变当前会话或新会话使用的模型（`pi.setModel` / `defaultProvider+defaultModel`） |
| 范围（scope） | `enabledModels` 限定的 `/model` 与 `Ctrl+P` 候选集 |
| 快照缓存 | pi 的 `models-store.json`，记录各 provider 上次成功发现的模型 |
