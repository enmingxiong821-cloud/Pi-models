# pi 接入任意第三方 API（中转站）—— 进度与调研存档

> 存档时间：2026-10-16 晚。下次接着干，先读这一页。

## 1. 目标

用户已装 `pi`（终端 AI 编码助手），但 pi 的登录/上手里只列内置模型厂商，
无法直接填第三方中转站（如 Crow5）。目标是做一个**方便接入任意第三方 API、
并且随时能切模型**的小程序。

## 2. 核心调研结论（重要，已在本机源码核实）

pi **原生**支持任意兼容端点，不需要写扩展。三条链路都在 `~/.pi/agent/` 下：

| 文件 | 作用 |
|---|---|
| `models.json` | 自定义 provider：`baseUrl` / `api` / `apiKey` / `headers` / `compat` / `models[]` / `modelOverrides{}` |
| `auth.json` | 凭据存储，形如 `{"<providerId>": {"type":"api_key","key":"sk-..."}}` |
| `settings.json` | `defaultProvider` / `defaultModel` / `defaultThinkingLevel` / `enabledModels` |

关键事实（来自 pi 1.3.0 自带文档 `docs/models.md`、`docs/custom-provider.md`、`schemas/models.schema.json`）：

1. `models.json` 里 `baseUrl` + `api: "openai-completions"` 即可接入大多数中转站
   （NewAPI / one-api / Ollama / LM Studio / vLLM 都走这条路）。OpenAI 系 baseUrl 要带 `/v1`，
   Anthropic 系（`anthropic-messages`）是不带 `/v1` 的根地址。
2. `api` 可选值：`openai-completions`、`openai-responses`、`anthropic-messages`；
   **模型级 `api` 和 `baseUrl` 会覆盖 provider 级**，所以一个中转站可以混挂 Claude + GPT。
3. 凭据优先级：`--api-key` > `auth.json` > `models.json.apiKey` > 环境变量。
   未解析到凭据的模型不会出现在 `/model` 里（常见"配了但不显示"原因）。
4. 切换方式（不用改配置文件）：pi 内 `/model`、`Ctrl+P` 循环、`--models` 限定循环范围、
   `settings.enabledModels` 持久化循环范围；命令行 `pi --provider X --model Y`。
5. 模型元数据（`contextWindow`、`maxTokens`、`reasoning`、`input`、`cost`）缺失会导致
   上下文管理/计费显示不准 —— 这是本工具要自动补全的重点。
6. pi 自带完整官方模型目录：`<pi安装目录>/node_modules/@earendil-works/pi-ai/dist/providers/data/*.json`
   （43 个文件，含 openrouter 大目录），可复用做元数据兜底。**注意其结构是两层**：
   `{ "<api名>": { "chat:<模型id>": {...完整元数据...} } }`。
7. 另有扩展路线：用户本机已装 `pi-provider-newapi`（`pi install git:github.com/ttimasdf/pi-provider-newapi`），
   它把 NewAPI 网关注册成独立 provider，命令是 `/newapi-provider-add`、`/login`、`/model`。
   已装但**尚未配置**（`~/.pi/agent/extension-settings/provider-newapi.json` 里 `providers: {}`）。
   本工具与它不冲突：工具走 `models.json` 原生路线，覆盖面更广（不要求网关是 NewAPI）。

## 5. 已完成的代码（本仓库 `仓库根`）

零依赖 Node CLI，命令名 `pmh`（`node bin/pmh.mjs`）：

| 文件 | 内容 |
|---|---|
| `bin/pmh.mjs` | 参数解析、命令分发、联网命令的代理自重启（Node 的 fetch 需 `NODE_USE_ENV_PROXY=1`） |
| `src/paths.mjs` | agent 目录解析（`--agent-dir` / `PMH_AGENT_DIR`）、pi 安装定位、官方目录定位 |
| `src/util.mjs` | 原子写 + 时间戳备份、彩色输出、表格 |
| `src/catalog.mjs` | 载入 pi 官方模型目录、模型 id 归一化匹配（去 vendor 前缀/日期后缀/点横线变体/模糊）、启发式兜底、生成 `models.json` 条目 |
| `src/relay.mjs` | `/v1/models` 探测、最小试聊请求（三种 API 协议）、NewAPI 倍率端点探测 |
| `src/commands.mjs` | `add / sync / key / ls / use / scope / test / run / pick / alias / rm / doctor` |
| `tools/smoke-test.mjs` | 端到端自测（默认进程内打桩 fetch；`--real` 走真实 HTTP + spawn CLI） |
| `tools/ws.mjs` | 检索/抓页小工具（沙箱里 curl 的 TLS 不可用，Node fetch 可用） |

已实现的命令语义：

```
pmh add crow5 --base https://xxx.crow5.com --key sk-xxx [--api ...] [--api-rule "^claude=anthropic-messages"]
pmh test crow5          # /v1/models + 真发一条最小请求
pmh use crow5#模型id     # 写 settings.json 默认模型
pmh run crow5#模型id     # 直接以该 provider/model 启动 pi
pmh pick [--run]        # 交互式选模型
pmh alias               # 生成 pi-<provider> 快捷函数
pmh ls / scope / sync / rm / key / doctor
```

设计取舍：密钥默认写 `auth.json`（与 pi 自身一致），`--key-in models` 可改写到 `models.json`；
`--cost-multiplier 0.2` 用于中转站折扣价折算；所有写入都会先备份成 `*.bak-<时间戳>`。

## 9. 环境备忘（踩过的坑）

- **沙箱内 curl 的 TLS 不可用**（`schannel: SEC_E_NO_CREDENTIALS`），抓网页要用 `node tools/ws.mjs`（Node fetch 正常）。
- **沙箱内子进程连不上父进程的 loopback 监听端口**（外网正常），自测因此改成进程内打桩。
- 用户级代理 `http://127.0.0.1:7890`（FlClash）在跑；Node 要用代理必须 `NODE_USE_ENV_PROXY=1`，
  `pmh` 对联网命令会自动重启进程加上该变量。
- 沙箱内 pi 自己写 `~/.pi/agent` 会被拒（`EPERM ... settings.json.lock`），属正常现象，真机终端里无此问题；
  要让工具写真实配置，需要提权执行一次。
- 测试脚本里**不要用替换 `console.log` 的方式抓子命令输出**：进度行会被一起吞掉，
  看起来像"静默退出/提前结束"。进度行统一走 `console.error`（stderr），输出抓取与显示互不干扰。
- pi 的 RPC 模式（`--mode rpc`）是很好的无头验证手段：`get_commands` 能确认扩展注册，
  `prompt` 发 `/命令` 能真正执行扩展命令，`get_state` 能确认模型被切换。

| 级别 | 问题 | 处理 |
|---|---|---|

| P0 | 32 字符的 Key 别名发生冲突时，截断后仍算出同名 → **死循环** | 先在 base 后腾出后缀长度再截断，并加 1000 次上限 |
| P1 | 重复传同一标量参数（如两个 `--agent-dir`）会变成数组，下游拿到错误类型 | 参数解析独立成 `src/args.mjs`；标量「后者生效」，只有 `apiRule/file/from/tag` 允许数组 |
| P1 | 纯文本导入把版本号、Markdown 表格当成 URL，造出假 provider | `looksLikeUrl` 收紧：只认协议、带 TLD 的域名、IPv4:端口；`url|key` 两段格式保留 |
| P1 | `pmh rm` 只删 provider，`settings.json` 仍指向它 | 同步清理 `defaultProvider`/`defaultModel`/`enabledModels`，并留备份 |
| P1 | `sync`/重导入时覆盖掉用户手改的 provider 级字段（`headers`、`compat` 等） | 改为以现有对象为底合并 |
| P1 | 注册表 JSON 损坏时写回不备份，等于把损坏现场覆盖掉 | 检测到原文件解析失败时强制备份 |
| P1 | `/v1/models` 响应无大小上限，超大响应会撑爆内存 | `readTextCapped` 流式累计，超过 8 MiB 中止 |
| P2 | 用户粘完整端点（`/v1/chat/completions`）会拼出双重路径 | `rootOf` 统一剥掉端点后缀与 `/v1` |

| P2 | NewAPI 的 `completion_ratio` 是数字时被忽略 | 数字与对象两种形状都认 |

| P2 | 同一秒内连续写两次，后一次备份会覆盖前一次 | 备份名冲突时追加 `-2`、`-3` |

## 8.8 2026-10-17 深夜：按任务难度自动路由

需求：接入与切换要方便，同时能按"项目/任务难度"自动选模型，用户可随时关闭，目标是
高质量完成任务又省 token。调研后确定的约束：**自动切换的最大风险不是选错档，而是打断 prompt cache**，
所以设计成"新任务分类、任务内粘滞"。

调研来源与结论：

- [LiteLLM AutoRouter / Heuristic v2](https://docs.litellm.ai/docs/routing)：按 prompt 长度、代码块、
  关键词做启发式打分，支持多档模型与 fallback；结论是两级路由（先粗分、再按档选模型）足够，
  不需要训练分类器。
- [OpenRouter Auto Router](https://openrouter.ai/docs/features/model-routing)：按任务类型与成本/质量
  偏好排序候选；结论是"用户要能看见为什么选这个模型"。
- [claude-code-router](https://github.com/musistudio/claude-code-router)：按场景（default/background/
  think/longContext）分模型，重试与长上下文单独路由；结论是后台/旁路请求应走便宜档。
- [RouteLLM](https://github.com/lm-sys/RouteLLM) / [NotDiamond](https://www.notdiamond.ai/) /
  Cursor Router 等：强弱模型二选一能显著降本，但需要质量兜底；结论是保留失败重试升档。
- GitHub Copilot 的自动模型选择：强调"任务内模型稳定 + 用户可手动覆盖"。

| 改动 | 内容 |
|---|---|
| `extensions/auto-router/router.mjs`（新增） | 单一事实来源：配置模型（三档/阈值/开关/pin）、容错归一化、原子读写、`classifyTask`、`tierForScore`/`bumpTier`/`parseTierSpec` |
| `extensions/auto-router/index.js`（新增） | `pi.registerVirtualModel` 注册 `pmh/auto`；按 `reason` 路由：`user` 分类、`continuation` 粘滞、`retry` 升一档、`direct` 走便宜档；状态存 `request.state`；注册 `/auto` |
| `pmh auto ...` | `status/on/off/set/unset/thresholds/pin/explain/install`，与扩展共用同一份配置 |
| `pmh install-extension` | 一并安装/刷新 auto-router 扩展（逐文件比较，内容变化才备份） |
| 补全与帮助 | `pmh auto <Tab>`、子命令与档位补全；帮助文本同步 |

设计要点：

- 虚拟模型只记一条 `model_change`，每次响应记录实际物理模型；相比扩展里频繁 `setModel()`，
  不污染会话恢复与默认值。
- 分类只发生在用户新消息；工具续跑沿用上一轮物理模型与思考档，重试最多升一档且只升一次。
- 档位缺失时按方向回退并只提醒一次，绝不因未配置而让会话报错；老版本 pi 只注册 `/auto` 并提示升级。
- 配置 `<agentDir>/extension-settings/pmh-auto.json` 不含密钥，扩展每个请求重读。
- 关闭方式：`/auto off`（pi 内）或 `pmh auto off`；关闭后固定 `standard`，不分类、不提示。

测试：新增 `tools/router-test.mjs`（20 项），覆盖分类器各类输入、配置容错、原子读写、
虚拟模型注册与四条路由分支、pin/关闭、重试升档只一次、未配置回退、`/auto` 子命令、
CLI 全子命令、拒绝与警告分支、`auto install` 复制文件。
