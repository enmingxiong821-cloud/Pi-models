# 资料 03：同类项目与 pi 生态

## 1. pi 自己的生态入口

| 入口 | 内容 |
|---|---|
| `https://pi.dev/` | 官方站点与文档 |
| `https://pi.dev/models` | 模型目录（provider / 模型 id / 能力 / 价格） |
| `https://pi.dev/packages` | **包目录**（本机查询时 5364 个包，可按名称/描述/类型筛选，含下载量与更新时间） |
| `https://github.com/earendil-works/pi` | 源码仓库（`pi-mono` 工具链：`pi-ai`、`pi-agent-core`、`pi-coding-agent`、`pi-tui`、`pi-mcp`…） |

### pi 包（Package）的形态

一个包就是"普通目录或 npm 包"，可以暴露约定目录，或在 `package.json` 的 `pi` 字段里显式声明：

```jsonc
{
  "name": "my-pi-package",
  "keywords": ["pi-package"],
  "pi": { "extensions": ["./src/extension.ts"], "skills": ["./resources/skills"] }
}
```

安装方式：`pi install npm:<pkg>` / `pi install git:github.com/<user>/<repo>` / `pi install ./local`；
临时试用：`pi -e <source>`。

> 本项目仓库根目录就是标准包布局（含 `extensions/`），所以 **`pi install git:github.com/enmingxiong821-cloud/pi-model` 即可直接装这个包**，
> 不需要发布到 npm。

### 自动路由 / 按难度选模型的参考实现

| 项目 | 做法 | 对本项目的结论 |
|---|---|---|
| [LiteLLM Router / AutoRouter](https://docs.litellm.ai/docs/routing) | Heuristic v2 按 prompt 长度、代码块、关键词打分，多档模型 + fallback | 启发式足够；两级路由（先分档、再按档选模型）比训练分类器更可控 |
| [OpenRouter Auto Router](https://openrouter.ai/docs/features/model-routing) | 按任务类型与成本/质量偏好排序 | 必须向用户展示"为什么选它"，否则不可信 |
| [claude-code-router](https://github.com/musistudio/claude-code-router) | 按场景分模型（default / background / think / longContext） | 后台与旁路请求单独走便宜档 |
| [RouteLLM](https://github.com/lm-sys/RouteLLM) / [NotDiamond](https://www.notdiamond.ai/) | 强弱模型二选一，按质量阈值兜底 | 需要失败重试升档，不能一次定生死 |
| Cursor Router / GitHub Copilot 自动选模型 | 任务内模型稳定，用户可手动覆盖 | 任务内粘滞 + pin/off 是必须项 |

关键教训：**自动切换最容易浪费 token**——同一任务里反复换模型会让 prompt cache 全部失效。
因此实现上只在用户新消息时分类，工具续跑沿用上一轮模型，重试最多升一档。

## 3. 本项目的差异点（对外表述时用这些）

1. **接入即配置**：一条 `pmh quick` 完成"URL+Key → 拉模型 → 补元数据 → 存配置 → 挑默认模型"。
2. **元数据自动对齐**：复用 pi 自带的官方模型目录（本机 1200+ 条），匹配不上才用启发式，价格不瞎猜。
3. **运行期切换**：`/switch`、`/switch-save`、`Ctrl+Shift+M` 直接在 pi 里换模型，中转站模型永远排最前。
4. **零依赖、可通读**：只用 Node 标准库；`src/` 约 4550 行（含中文注释），扩展 608 行，测试 2280 行。
5. **跨平台且可验证**：平台差异集中在两个可注入模块里，任意系统都能跑完三平台分支的单测。
6. **难度自适应且可关闭**：`pmh/auto` 虚拟模型按任务难度在三档模型间选择，任务内不换模型以保护
   prompt cache；`/auto off`、`/auto pin`、阈值可调，配置不含密钥。
7. **不 patch pi 本体，升级自动适配**：只用官方扩展/包机制；启动时校验 pi 版本与扩展 API，
   copy 模式自动同步最新文件，API 不兼容只降级 `/auto`，不影响 `/switch` 与 pi 启动。

## 4. 命名与占用调研（2026-10-17 实测）

| 名称 | GitHub | npm |
|---|---|---|
| `pi-model` | 多个重名但都不相关（PINTO_model_zoo 等） | **已被占用** |
| `pi-model-hub` | `keambar/pi-model-hub`（★0、无描述） | **已被占用** |
| `pi-quick-switch` | 只有不相关结果 | 可用 |
| `pi-relay-hub` | 无人使用 | —— |

因此：**仓库名用 `pi-model`**（最终落地 `enmingxiong821-cloud/pi-model`），`package.json` 的 npm 名保留 `pi-model-hub`
（避免与既有 npm 包冲突）；如果要发布到 npm，需要再换一个未被占用的名字。

## 6. cc-switch 的可复用格式（2026-10-17 核实）

来源：[配置 FAQ](https://github.com/farion1231/cc-switch/blob/main/docs/user-manual/en/5-faq/5.1-config-files.md)、
[深链 FAQ](https://github.com/farion1231/cc-switch/blob/main/docs/user-manual/en/5-faq/5.3-deeplink.md)、
[deeplink/provider.rs](https://github.com/farion1231/cc-switch/blob/main/src-tauri/src/deeplink/provider.rs)。

**配置位置**：`~/.cc-switch/`。v3.8.0 起主存储迁移到 SQLite `cc-switch.db`，
旧版 `config.json` 首次启动会被迁移但保留，可作为只读导入源。

**旧版 JSON 形状**（v2/v3）：

```json
{"version":2,
 "claude":{"providers":{"<id>":{
   "name":"…","settingsConfig":{"env":{"ANTHROPIC_BASE_URL":"…","ANTHROPIC_AUTH_TOKEN":"…"}}
 }},"current":"<id>"},
 "codex":{"providers":{"<id>":{"settingsConfig":"[model_providers.x]\n…"}}},
 "gemini":{…}}
```

**分享深链**（官方唯一的单供应商分享方式）：

```text
ccswitch://v1/import?resource=provider&app=pi&name=…&endpoint=…&apiKey=…&model=…&apiFormat=…
```

- `apiFormat`：`anthropic` → `anthropic-messages`；`openai_chat` → `openai-completions`；
  `openai_responses` → `openai-responses`；`gemini_native` → `google-generative-ai`（本项目暂未支持）。
- `model` 对 `app=pi` 是必填，解析阶段缺了会直接报错。
- `config` / `content` 是整段配置的 Base64 + URL 转义；其余参数是普通 URL 编码明文。

`pmh import` 已支持该深链与旧版 `config.json`（`--from ccswitch`）；v4 检测到 `cc-switch.db`
时只提示改用深链，不引入 SQLite 依赖。cc-switch v4 的整库导出是 SQL dump，没有单供应商 JSON
分享格式（[issue #964](https://github.com/farion1231/cc-switch/issues/964) 仍在请求中）。
