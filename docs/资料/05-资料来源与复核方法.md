# 资料 05：资料来源与复核方法

> 所有结论都标了来源。**pi 内部机制类的内容会随版本变化**，怀疑过期时按第 3 节重跑一遍。

## 1. 一手来源（本机 pi 安装目录）

版本：**pi 1.3.0**；根目录 `<PI>=%USERPROFILE%\.pi\agent\install\releases\1.3.0\node_modules\@earendil-works\pi-coding-agent`

### 1.1 文档（`<PI>/docs/`）—— 本项目的结论主要来自这里

| 文件 | 讲什么 | 本项目用到的信息 |
|---|---|---|
| `models.md` | 选模型、`models.json` 自定义端点、采样参数、分类/图片模型、排错 | "配置兼容端点"的字段与语义；凭据顺序 |
| `providers.md` | 各 provider 的登录方式与环境变量、Azure/Bedrock/Vertex 细节 | 环境变量表、`/login` 与凭据存储 |
| `custom-provider.md` | 什么时候该写扩展 provider | 判定"我们不需要写 provider 扩展"的依据 |
| `settings.md` | 全部设置项 | `defaultProvider`/`defaultModel`/`enabledModels`/`defaultThinkingLevel` |
| `extensions.md` | 扩展的加载位置、生命周期、能力矩阵 | 扩展放在 `~/.pi/agent/extensions/`、jiti 加载 TS |
| `virtual-models.md` | 虚拟模型与路由 | 路线图里的"同站降级/升级路由" |
| `rpc.md` / `rpc-commands.md` / `rpc-extension-ui.md` | RPC 模式的命令与事件 | 无头验证扩展是否被加载、切换是否生效 |
| `keybindings.md` | 键位格式与默认键位 | 选 `ctrl+shift+m` 并确认无冲突、`/hotkeys` |
| `environment-variables.md` | 全部 `PI_*` 变量 | `PI_CODING_AGENT_DIR` 等 |
| `packages.md` | pi 包格式与安装方式 | "仓库根目录即标准包"的分发方式 |
| `windows.md` / `termux.md` / `containerization.md` / `terminal-setup.md` | 各平台注意事项 | 跨平台适配依据 |
| `security.md` / `configuration.md` | 安全与配置目录 | 密钥存放与备份策略 |

### 1.2 Schema（`<PI>/schemas/`）

| 文件 | 用途 |
|---|---|
| `models.schema.json` | **`models.json` 的字段全集**（provider 级、模型级、`compat` 全部开关都在这里） |
| `settings.schema.json` | `settings.json` 的字段全集 |
| `keybindings.schema.json` | 键位定义 |

`.../node_modules/@earendil-works/pi-ai/dist/providers/data/*.json`（本机 43 个文件，展平约 1200+ 条）

### 1.4 参考实现（读源码可以确认行为细节）

| 路径 | 内容 |
|---|---|
| `.../pi-coding-agent/dist/core/extensions/types.d.ts` | ExtensionAPI / ExtensionContext / RegisteredCommand / ExtensionUIContext 的完整签名 |
| `.../pi-coding-agent/dist/core/model-registry.d.ts` | `getAvailable/find/getProviderAuthStatus/streamSimple` 等方法 |

## 3. 怎么自己复核（可复制粘贴）

### 3.1 确认 pi 版本与安装位置

```powershell
node bin/pmh.mjs doctor
```

### 3.2 重读 schema（字段是否还一样）

```powershell
$pi = "$env:USERPROFILE\.pi\agent\install\releases\<版本>\node_modules\@earendil-works\pi-coding-agent"
Get-Content -Raw "$pi\schemas\models.schema.json" | Select-Object -First 1
```

### 3.3 检查官方模型目录的结构与规模

```powershell
$data = "$env:USERPROFILE\.pi\agent\install\releases\<版本>\node_modules\@earendil-works\pi-ai\dist\providers\data"
(Get-ChildItem $data).Count
node -e "const j=require('fs').readFileSync(process.argv[1]+'/anthropic.json','utf8');const o=JSON.parse(j);console.log(Object.keys(o), Object.keys(o[Object.keys(o)[0]]).slice(0,3))" $data
```

### 3.4 确认扩展 API 的签名

```powershell
Select-String -Path "$pi\dist\core\extensions\types.d.ts" -Pattern "setModel|registerShortcut|registerCommand" -Context 0,2
```

### 3.5 无头验证扩展是否真的能切模型

```powershell
node tools/rpc-test.mjs            # 隔离配置目录，跑完整流程
node tools/rpc-test.mjs --discover # 用真实 ~/.pi/agent 验证自动发现
```

### 3.6 探测网络与端点（Node fetch 才读代理）

```powershell
$env:NODE_USE_ENV_PROXY='1'
node -e "for (const u of ['https://registry.npmmirror.com/','https://api.deepseek.com/v1/models']) { try { const r = await fetch(u,{signal:AbortSignal.timeout(12000)}); console.log(r.status, u) } catch (e) { console.log('ERR', e.cause?.code ?? e.message, u) } }"
```

### 3.7 抓网页 / 搜索（本机 curl 的 TLS 在沙箱里不可用，用 Node）

```powershell
node tools/ws.mjs search "pi coding agent custom provider" 8
node tools/ws.mjs get "https://pi.dev/packages?q=provider" 6000
```

### 3.8 检查换行与脚本可执行位（跨平台回归）

```powershell
git ls-files --eol bin/pmh install.sh 一键安装.cmd
git ls-files -s bin/pmh bin/pmh.mjs     # 100755 表示带可执行位
```

## 4. 时效性提醒

| 事实 | 会不会变 | 变了怎么办 |
|---|---|---|
| pi 的配置字段与 schema | 会（随版本） | 重读 `schemas/models.schema.json`；`pmh doctor` + 自测会先暴露问题 |
| 官方模型目录结构（两层） | 可能 | `src/catalog.mjs` 已同时兼容"两层"与"平铺"两种形状 |
| 扩展 API 签名 | 会 | 对照 `dist/core/extensions/types.d.ts` |
| npm / GitHub 名称占用 | 会 | 见 [03-同类项目与生态.md](03-同类项目与生态.md) 第 4 节 |
| 中转站的具体端点与政策 | 会 | 以站点自己登录后的文档为准，本工具不硬编码任何站点 |
