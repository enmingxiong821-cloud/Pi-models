# 资料 04：跨平台适配

## 1. pi 官方给各平台的说明（要点摘录）

### Windows（`docs/windows.md`）

- pi 可以原生跑在 Windows，也可以在 WSL 里跑；原生模式下 `bash` 工具默认用 **Git Bash**，可选启用 `powershell` 工具。
- Bash 解析顺序：`~/.pi/agent/settings.json` 的 `shellPath` → `Program Files` / `Program Files (x86)` 下的 Git Bash → PATH 上的 `bash.exe`。
- 想用 PowerShell 工具：`settings.json` 里 `"defaultTools": ["read", "powershell", "edit", "write"]`。
- 验证命令：在 pi 里 `!printf 'Bash is working\n'`。

### Android / Termux（`docs/termux.md`）

- 通过 Termux 运行；`pkg install nodejs git` 后安装 pi。
- 文本输入、文件工具、shell 命令都可用；剪贴板文本需要 **Termux:API**（`termux-clipboard-get` 等）。
- **不支持剪贴板图片粘贴**。

### 其他

- `docs/containerization.md`（容器）、`docs/terminal-setup.md`（终端能力探测）也值得看，遇到渲染/粘贴问题先从这两份找。

## 2. 平台差异与本项目的处理

| 关注点 | Windows | macOS | Linux | WSL | Termux |
|---|---|---|---|---|---|
| 入口脚本 | `bin/pmh.cmd` | `bin/pmh`(POSIX) | `bin/pmh` | `bin/pmh` | `bin/pmh` |
| 安装脚本 | `一键安装.cmd` → `install.ps1` | `install.sh` | `install.sh` | `install.sh` | `install.sh`（认 `$PREFIX/bin`） |
| 配置目录 | `%USERPROFILE%\.pi\agent` | `~/.pi/agent` | `~/.pi/agent` | `~/.pi/agent`（跨到 Windows 侧用 `--agent-dir /mnt/c/Users/<你>/.pi/agent`） | `~/.pi/agent` |
| 启动器 | `pi.cmd`；**必须走 shell**，路径含空格必须加引号 | `~/.pi/agent/bin/pi`、`/opt/homebrew/bin/pi` | `~/.pi/agent/bin/pi`、`/usr/local/bin/pi`、`~/.local/bin/pi` | 同 Linux | 同 Linux |
| 剪贴板 | `pwsh` → `powershell` 的 `Get-Clipboard -Raw` | `pbpaste`（自带） | `wl-paste`（Wayland）→ `xclip` → `xsel` | 同 Linux | `termux-clipboard-get`（需 termux-api） |
| PATH 惯例 | 用户级 Path 环境变量 | `/opt/homebrew/bin`、`~/.local/bin` | `/usr/local/bin`、`~/.local/bin` | 同 Linux | `$PREFIX/bin` |
| 换行 | `.cmd`/`.ps1` = CRLF；脚本 = LF | LF | LF | LF | LF |

### 剪贴板工具怎么装

```bash
# Linux (Wayland)          Linux (X11)            Termux
sudo apt install wl-clipboard   sudo apt install xclip     pkg install termux-api
```

`pmh doctor` 会直接告诉你当前机器上找到的是哪一个，没找到会提示上面这些安装方式。

## 3. 容易被忽略的三个坑

### 3.1 换行符会让 shell 脚本彻底跑不起来

如果 `.sh` / 无扩展名脚本以 CRLF 提交，在 Linux/macOS 上会报 `bad interpreter: /bin/sh^M`。
本项目用 `.gitattributes` 强制：

```gitattributes
* text=auto
*.sh text eol=lf
bin/pmh text eol=lf
*.mjs text eol=lf
*.cmd text eol=crlf
*.ps1 text eol=crlf
```

并且提交时跑过 `git add --renormalize .`，用 `git ls-files --eol <文件>` 可以核对 index/工作区两侧的换行。

### 3.2 Windows 上路径含空格

`C:\Users\John Doe\.pi\agent\bin\pi.cmd` 直接丢给 shell 会在空格处被截断。
`launcherCommand()` 会在需要走 shell 且路径含空格时加引号（有单测覆盖）。

### 3.3 Node 版本决定能不能直接跑 TypeScript

Node 20 没有"类型擦除"，`import "./x.ts"` 会失败；Node 22.6+ / 24 才能直接跑 `.ts`。
所以 pi 扩展用**纯 JS** 写（pi 的 jiti 两者都支持），这样任意 Node 20+ 都能加载与测试。

## 4. 终端能力的兜底

| 能力 | 用在哪 | 不可用时 |
|---|---|---|
| raw mode（逐键读取） | 掩码输入 Key、↑↓ 选择器 | 掩码输入退化为明文（会 warn）；选择器退化为"输序号" |
| ANSI 转义（清行/光标上移） | 选择器重绘 | 仅在 TTY 下启用；非 TTY 直接走纯文本路径 |
| 是否 TTY | 决定要不要提问 | 非 TTY 全部走参数模式；也可 `PMH_NONINTERACTIVE=1` 强制 |

## 5. 验证方式与局限

| 手段 | 能做到什么 | 局限 |
|---|---|---|
| `tools/platform-test.mjs`（13 项） | 在任意系统上把 Windows / macOS / Linux 三套分支都跑一遍（剪贴板候选与回退、启动器查找、引号、名称推断） | 验证的是逻辑分支，不是真机集成 |
| Git Bash 实跑 `bin/pmh` | POSIX 入口语法与执行链路（Git Bash 就是 POSIX sh） | 不等于真 Linux/macOS |
| GitHub Actions 矩阵 | ubuntu / windows / macos × Node 20/22/24 真实执行四套测试 | 需要能读 Actions 结果（私有仓库需登录） |
| 本机沙箱 | —— | Docker daemon 与 WSL 在本会话都不可用（`E_ACCESSDENIED`），所以无法本地起真 Linux |

## 6. 各平台出问题时的排查顺序

1. `pmh doctor`：先看系统/TTY/剪贴板/启动器/配置路径这四行。
2. `node -v`：必须 ≥ 20。
3. `pmh ls`：凭据那一列是不是"无"。
4. `pmh test <名称> --verbose`：看是 `/v1/models` 失败还是试聊失败，`--verbose` 会打印响应片段。
5. 网络：`HTTPS_PROXY` 是否设了、FlClash/Clash 是否在跑；不行就 `--proxy` 或 `PMH_NO_PROXY=1`。
6. 配置损坏：`pmh doctor` 会标出是哪个 JSON 坏了；旁边有 `*.bak-<时间戳>` 可以回滚。
