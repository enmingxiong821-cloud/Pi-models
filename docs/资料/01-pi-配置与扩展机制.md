# 资料 01：pi 的配置与扩展机制

> 结论基于本机安装的 **pi 1.3.0**（`@earendil-works/pi-coding-agent`），所有事实都能在安装目录里复核，
> 复核命令见 [05-资料来源与复核方法.md](05-资料来源与复核方法.md)。

## 1. 目录布局（agent 目录）

默认 `~/.pi/agent`，可用环境变量 `PI_CODING_AGENT_DIR` 覆盖（本工具的 `--agent-dir` / `PMH_AGENT_DIR` 等价）。

| 路径 | 作用 |
|---|---|
| `settings.json` | 全局设置：默认模型、思考级别、包声明、工具集、`enabledModels` 等 |
| `auth.json` | 凭据存储：`{"<provider>": {"type":"api_key","key":"..."}}` |
| `models.json` | **用户自定义 provider / 模型**（本工具的主要写入目标） |
| `models-store.json` | pi 缓存的各 provider 模型目录快照（离线可用） |
| `extensions/` | 用户级扩展：单文件 `.ts/.js` 或含 `index.ts/js` 的子目录 |
| `extension-settings/` | 各扩展自己的配置（如 `provider-newapi.json`） |
| `sessions/` | 会话记录（JSONL） |
| `npm/`、`git/` | `pi install npm:...` / `git:...` 安装的包 |
| `install/` | managed install：`current-version` + `releases/<版本>/node_modules/...` |
| `bin/` | 启动器 `pi.cmd`（Windows）/ `pi`（类 Unix）、以及附带的 `fd.exe`、`rg.exe` |

## 2. 凭据解析顺序（决定模型是否"可见"）

1. 运行时 `--api-key`
2. `auth.json` 里该 provider 的凭据
3. `models.json` 里该 provider 的 `apiKey`
4. 该 provider 的环境变量（如 `OPENAI_API_KEY`）或云上 ambient 凭据

> **解析不到凭据的模型不会出现在 `/model` 里**。这是"配置写了却看不到"的第一大原因。
> `models.json` 的 `apiKey` 支持 `$ENV` / `${ENV}` / 字面量 / `!command`（命令在请求时执行，不缓存）。

## 3. 模型选择与切换

| 机制 | 说明 |
|---|---|
| `/model` | 搜索并选择模型；`Ctrl+S` 可存为新会话默认 |
| `Ctrl+P` | 在候选模型间循环 |
| `enabledModels` | `settings.json` 里用模式（glob/模糊）限定候选集，影响启动选择与 `Ctrl+P` |
| `--models <patterns>` | 命令行版的候选集限定 |
| `--provider X --model Y` | 直接以某模型启动 |
| `--model "provider/id:high"` | 模型 + 思考级别一起指定 |
| `/thinking` | 切换思考级别；`Ctrl+S` 存为启动级别 |
| `/scoped-models` | 交互式管理循环范围并保存 |
| `defaultProvider` / `defaultModel` / `defaultThinkingLevel` | 新会话的默认值 |

会话内切换会被记进会话记录（`model_change` / `thinking_level_change`），恢复会话时沿用，不改全局默认。

## 4. `models.json` 的关键字段

### provider 级

| 字段 | 说明 |
|---|---|
| `baseUrl` | 端点。**OpenAI 系要带 `/v1`，`anthropic-messages` 用根地址** |
| `api` | `openai-completions` / `openai-responses` / `anthropic-messages`（也可为模型级覆盖） |
| `apiKey` | 密钥，支持 `$ENV`、`${ENV}`、`!command`、字面量 |
| `headers` | 额外请求头 |
| `name` | 显示名 |
| `models[]` | 模型列表；按 `id` 替换同名模型 |
| `modelOverrides{}` | 只改元数据、不替换列表（用于内置/扩展模型或中转代理） |
| `compat{}` | 兼容性开关（见下） |

### 模型级常用字段

`id`（必填）、`name`、`api`、`baseUrl`、`reasoning`、`input[]`、`contextWindow`、`maxTokens`、`cost{}`、
`promptCache{short,long}`、`samplingParams`、`samplingParamsByThinkingLevel`、`thinkingLevelMap`、`inputLimits`、`compat`。

### `compat` 里几个值得知道的开关（中转站场景常踩）

| 字段 | 用途 |
|---|---|
| `sendSessionAffinityHeaders` | 网关按会话粘性路由时必须开 |
| `supportsUsageInStreaming` | 流式是否返回 usage（关掉会影响计费显示） |
| `maxTokensField` | `max_tokens` 还是 `max_completion_tokens` |
| `thinkingFormat` | 思考参数的格式（openai / openrouter / deepseek / zai / qwen …） |
| `supportsStrictTools`、`supportsCacheControlOnTools` | 工具 schema / 缓存标记的兼容性 |
| `supportsMidConvoSystemMessages` | 是否允许会话中途插入 system 消息 |

> 官方提醒：这些开关描述的是"已核实的差异"，**不要因为端点自称兼容就打开**。

## 5. 扩展机制

- 位置：用户级 `~/.pi/agent/extensions/`、项目级 `.pi/extensions/`（需项目信任）、或用 `--extension <路径>` 临时加载。
- 形态：单文件 `.ts` / `.js`，或含 `index.ts|js` 的目录；pi 用 **jiti** 加载 TypeScript，无需编译。
- 入口：`export default function (pi: ExtensionAPI) { ... }`，工厂可以是 async（pi 会等它完成再继续启动）。

### ExtensionAPI 常用面（本工具用到的）

| API | 用途 |
|---|---|
| `pi.registerCommand(name, { description, handler, getArgumentCompletions })` | 注册 `/命令`；handler 收到 `(args, ctx)` |
| `pi.registerShortcut("ctrl+shift+m", { description, handler })` | 注册快捷键；键位格式 `modifier+key` |
| `pi.setModel(model)` / `pi.getThinkingLevel()` / `pi.setThinkingLevel(l)` | 改当前会话的模型与思考级别（**不改全局默认**） |
| `pi.getSettings()` | 读合并后的有效设置 |
| `pi.registerProvider()` / `pi.registerVirtualModel()` | 注册 provider / 虚拟模型（本工具没用到，走 models.json） |
| `pi.registerTool()`、`pi.registerFlag()`、`pi.registerEntryRenderer()` | 工具、命令行开关、自定义渲染 |
| `pi.exec(cmd, args)` | 执行外部命令 |

### 扩展上下文 `ctx`

| 字段 | 用途 |
|---|---|
| `ctx.model` | 当前模型 `{ provider, id, name, reasoning, contextWindow, maxTokens, input… }` |
| `ctx.modelRegistry` | `getAll()` / `getAvailable()`（已按凭据过滤）/ `find(provider, id)` / `streamSimple()` |
| `ctx.ui` | `select(title, options)` / `confirm` / `input` / `notify` / `setStatus` / `setWidget` / `onTerminalInput` |
| `ctx.sessionManager` | 会话条目、分支、压缩 |
| `ctx.executeTool(name, args)` | 在工具内部调用其他工具（结果只回给调用者） |

事件（`pi.on("...")`）覆盖 `session_start`、`before_agent_start`、`message_*`、`tool_call`/`tool_result`、
`turn_end`、`agent_before_settle`、`model_select`、`thinking_level_select`、`before_provider_request` 等，
可用于拦截与改写；本工具目前只用到命令/快捷键，没有挂事件。

## 6. RPC 模式（无头验证的利器）

`pi --mode rpc` 以 JSONL 在 stdio 上收发命令与事件。常用命令：

| 命令 | 用途 |
|---|---|
| `get_commands` | 列出可用命令（扩展命令也在里面）——**用来验证扩展是否真的被加载** |
| `prompt` | 发用户消息；`message` 以 `/` 开头会执行对应的扩展命令 |
| `get_state` / `get_messages` | 读当前状态（含 `provider`/`model`）——**用来验证切换是否生效** |
| `set_model` / `cycle_model` / `get_available_models` | 直接切模型、循环、列可用模型 |
| `set_thinking_level` / `get_available_thinking_levels` | 思考级别 |
| `bash` / `abort` / `compact` / `switch_session` / `export_html` | 其他能力 |

本项目的 `tools/rpc-test.mjs` 就是：起 pi（`--mode rpc --offline --no-session --extension …`）→ `get_commands`
确认 `/switch` 存在 → `prompt "/switch gemini"` → `get_state` 确认模型真的变了。

## 7. 官方模型目录（元数据来源）

路径：`<install>/releases/<版本>/node_modules/@earendil-works/pi-ai/dist/providers/data/*.json`（本机 43 个文件）。
结构是**两层**：

```jsonc
{
  "anthropic-messages": {          // 第一层：API 名
    "chat:claude-sonnet-4-5": {    // 第二层：<类型>:<模型 id>
      "id": "claude-sonnet-4-5",
      "name": "Claude Sonnet 4.5",
      "reasoning": true,
      "input": ["text", "image"],
      "contextWindow": 200000,
      "maxTokens": 64000,
      "cost": { "input": 3, "output": 15, "cacheRead": 0.3, "cacheWrite": 3.75 }
    }
  }
}
```

类型前缀有 `chat:`、`image:`、`classifier:`；本工具只索引 `chat`（分类/图片模型不进 `/model`）。
本机展平后约 1200+ 条；`openrouter.json` 是最大的一份，条目的 id 带 vendor 前缀（`anthropic/claude-…`），
所以在同 id 冲突时优先级低于厂商专有文件。

## 8. 其他相关环境变量

| 变量 | 作用 |
|---|---|
| `PI_CODING_AGENT_DIR` | 覆盖配置目录（本工具也认） |
| `PI_CODING_AGENT_SESSION_DIR` | 覆盖会话目录 |
| `PI_MANAGED_INSTALL_ROOT` | 启动器传给 pi 的安装根（本工具的 RPC 测试会自己设置） |
| `PI_OFFLINE` / `--offline` | 关掉启动期网络动作（做无头测试时很有用） |
| `PI_SKIP_VERSION_CHECK`、`PI_TELEMETRY` | 关版本检查与遥测 |
| `PI_PROVIDER` / `PI_MODEL` / `PI_REASONING_LEVEL` | pi 给子进程的当前选择（可用于脚本判断） |
