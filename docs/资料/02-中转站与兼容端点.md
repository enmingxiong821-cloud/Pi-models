# 资料 02：中转站与兼容端点

## 1. 三种协议对照（本工具支持的）

| 项目 | `openai-completions` | `openai-responses` | `anthropic-messages` |
|---|---|---|---|
| 典型路径 | `POST {root}/v1/chat/completions` | `POST {root}/v1/responses` | `POST {root}/v1/messages` |
| 模型列表 | `GET {root}/v1/models` | 同左 | 同左（Anthropic 也有 `/v1/models`） |
| 鉴权头 | `Authorization: Bearer <key>` | 同左 | `x-api-key: <key>` + `anthropic-version` |
| `models.json` 的 `baseUrl` | 要带 `/v1` | 要带 `/v1` | 用**根地址**（不带 `/v1`） |
| 适配范围 | 绝大多数中转站、Ollama、LM Studio、vLLM、SGLang | 官方 OpenAI、部分网关 | Claude 官方、Anthropic 兼容通道 |

中转站里"Claude 走 Anthropic 通道"很常见（能拿到思考与缓存特性）。一个 provider 里混挂两种协议时：

```bash
pmh add crow5 --base https://x.crow5.com --key sk-xxx \
  --api-rule "^claude=anthropic-messages"      # claude* 走 Anthropic，其余走 OpenAI
```

本工具内部按 `modelApiOverrides` 的语义实现：逐条正则匹配，首个命中生效；模型级 `api` 会同时带上模型级 `baseUrl`。

## 2. 常见端点与用途

| 端点 | 用途 | 备注 |
|---|---|---|
| `/v1/models` | 模型列表 | 最通用的探测点；有的站不鉴权，有的站 401 |
| `/v1/chat/completions` | 对话 | 最小验证请求：`max_tokens: 8` + 一句 ping |
| `/v1/responses` | Responses 协议 | 自定义模型需要显式 `baseUrl` |
| `/api/ratio_config` | NewAPI 公布的模型倍率 | 可选端点；用于估算真实价格 |
| `/v1/models/user` | OpenRouter 专用：按 key 过滤后的模型与价格 | 网关代理常缺这个端点，缺了会退回全量列表 |

## 3. NewAPI / one-api 系网关

- 它们是"API 分发站"软件本体（[NewAPI](https://github.com/QuantumNous/new-api)、one-api），国内多数中转站基于它们。
- 模型列表 `/v1/models` 通常可用；有的要求鉴权，有的允许匿名。
- 倍率配置（`/api/ratio_config`）包含 `model_ratio`、`completion_ratio`、分组倍率等 —— 换算成真实价格要乘 `0.002/1K` 之类的基准，
  规则随版本变化，所以本工具**不自动换算**，只提供 `--cost-multiplier` 让用户表达折扣。
- 是否支持 Anthropic 通道取决于站点配置（有的只做 OpenAI 兼容）。

## 4. 计费与价格的处理原则

| 方案 | 命令 | 适用 |
|---|---|---|
| 官方参考价 | 默认 | 想看到大致量级 |
| 折扣折算 | `--cost-multiplier 0.2` | 站点按比例计价（如 2 折） |
| 不显示价格 | `--no-cost` | 完全不在意 / 怕误导 |

原则：**官方目录里没有的模型就留空价格**，不凭空生成数字。

## 5. 常见坑清单

1. **`baseUrl` 带不带 `/v1`**：OpenAI 系要带，Anthropic 系不带；本工具会按 `--api` 自动规范，并允许模型级覆盖。
2. **`/v1/models` 401 但聊天正常**：有些站不给列模型。此时用 `--model id1,id2` 手动指定，或 `--models-file`。
3. **配了却看不到模型**：凭据没解析到（`pmh ls` 会显示凭据来源）。
4. **响应不是 JSON**：网关返回 HTML 错误页时会这样；`pmh test --verbose` 会打印前 400 字符。
5. **流式不带 usage**：费用显示会偏；必要时在 `compat` 里调 `supportsUsageInStreaming`。
6. **工具调用被拒**：部分网关的 strict 模式或 `cache_control` 支持不全，见 `compat.supportsStrictTools` / `supportsCacheControlOnTools`。
7. **会话粘性**：网关按会话路由时必须 `compat.sendSessionAffinityHeaders: true`。
8. **国内访问海外站**：Node 的 `fetch` 默认不读系统代理，需要 `NODE_USE_ENV_PROXY=1`（本工具对联网命令自动加），
   或 `--proxy http://127.0.0.1:7890`，或 `PMH_NO_PROXY=1` 直连。

## 6. Crow5 的调研现状（未闭环）

| 已知 | 内容 |
|---|---|
| 品牌 | `crow5.com`，NZSK 逆转时空集团旗下 AGI 品牌，主打桌面 IDE（内测邀请制，v1.3.27） |
| 用户中心 | `user.crow5.com`（SPA，需登录）：激活码、设备授权、用量 |
| 中转端点 | 存在 `*.crow5.com` 形式的 API 路由（第三方探测站记录到 `tbyunyi-router.crow5.com`） |
| 文档 | 公开渠道只有产品文档页（`www.crow5.com/product-docs-v6.38.0.html`），**API base URL 与鉴权说明在登录后** |
| 缺什么 | 确切的 base URL 形态（是否 `/v1`）与 Key → 拿到后 `pmh quick <url> <key>` 即可闭环 |

本工具不依赖 Crow5 的任何专有特性：只要是 OpenAI / Anthropic 兼容端点就能接。
